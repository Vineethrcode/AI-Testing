==================================================
1. PROJECT PURPOSE
==================================================

We are building an AI-powered QA RAG application.

The application allows a user to upload QA-related documents and then ask natural-language questions about the contents.

The RAG should:
1. Accept QA documents.
2. Extract their text.
3. Clean the text.
4. Chunk the text intelligently.
5. Generate embeddings.
6. Store vectors in Vectra.
7. Retrieve relevant information for a question.
8. Give the retrieved context to a local LLM through Ollama.
9. Generate a grounded answer.
10. Avoid hallucinating when information is not available.

The current technology stack includes:
- Node.js
- Express
- Vectra / LocalIndex
- Ollama
- Embedding model: nomic-embed-text
- Chat model: gemma3:4b
- JavaScript
- Frontend/local web application

The current QA documents are:

7. DETERMINISTIC EXACT-ID LOOKUP FIX
==================================================

We changed the retrieval logic to use Vectra's:

listItems()

API.

The system now:
1. Performs normal semantic retrieval.
2. Extracts Test Case IDs from:
   - the user question
   - semantic retrieval results
3. Uses listItems() to inspect all indexed items.
4. Performs deterministic matching against the stored text.
5. Uses a regex similar to:

Test Case ID:\s*<ID>(?!\d)

6. Searches across ALL indexed documents.
7. Merges exact-ID results with semantic results.
8. Deduplicates results.
9. Preserves metadata such as:
   - id
   - documentName
   - page
   - text
   - score
   - chunkId

This was a major improvement.

==================================================
8. SECOND RETRIEVAL BUG
==================================================

There was another bug introduced by the deterministic lookup.

Exact matches were initially assigned:

score: 1

But later the source score was normalized using:

1 - result.score

Therefore:

1 - 1 = 0

The exact match became score 0.

The grounding logic used:

sources.length > 0 && sources[0].score >= 0.16

Therefore exact matches could incorrectly be treated as ungrounded.

We fixed this.

The current retrieval logic allows deterministic exact-ID matches to be treated as high-confidence results without simply disabling the grounding system.

DO NOT remove grounding or set the threshold to zero just to make answers appear.

async function retrieve(question, topK) {
  await ensureIndex();
  const [queryVector] = await embed([question]);
  const initialResults = await index.queryItems(queryVector, topK);

  const extractedIds = new Set();

  for (const match of question.matchAll(/Test Case ID:\s*(\d+)/gi)) {
    extractedIds.add(String(match[1]).trim());
  }

  for (const result of initialResults) {
    const text = String(result?.item?.metadata?.text || '');

    for (const match of text.matchAll(/Test Case ID:\s*(\d+)/gi)) {
      extractedIds.add(String(match[1]).trim());
    }
  }

  const exactResults = [];
  const allIndexedItems = await index.listItems();

  for (const testCaseId of extractedIds) {
    const exactPattern = new RegExp(
      `Test Case ID:\\s*${testCaseId}(?!\\d)`,
      'i'
    );

    for (const item of allIndexedItems) {
      const text = String(item?.metadata?.text || '');

      if (exactPattern.test(text)) {
        exactResults.push({
          item,
          score: 1
        });
      }
    }
  }

  const dedupedResults = [];
  const seen = new Set();

  for (const result of [...initialResults, ...exactResults]) {
    const metadata = result?.item?.metadata || {};

    const key =
      metadata.id ||
      `${metadata.documentName || 'unknown'}-${metadata.chunkId ?? 'chunk'}-${metadata.text || ''}`;

    if (seen.has(key)) continue;

    seen.add(key);
    dedupedResults.push(result);
  }

  const sources = dedupedResults.map((result) => {
    const metadata = result?.item?.metadata || {};

    return {
      id: metadata.id,
      documentName: metadata.documentName,
      page: metadata.page,
      text: metadata.text,
      score: ...,
      chunkId: metadata.chunkId,
    };
  });

  return {
    sources,
    grounded: ...
  };
}
